# One NAND image for every speaker

`make os` builds the one rootfs, and `make stu` packages it as the one universal STU for all
four models (ST10, ST20, Wireless Link and ST300; the packager's target is `soundtap-tri`)
with the packager and dry runs of `os/installer/build-universal-stu.sh`.

- **Kernel**: one, from `image/linux.fragment` on top of omap2plus: the configuration
  of the kernel the universal STU has shipped since the script pipeline (removed 2026-10-01) built it. WiLink, Bluetooth (with its init script,
  via `os/external.mk`) and the infrared receiver are built in; USB is the MUSB dual-role stack.
  The command line is empty: every model's line comes from its own U-Boot environment.
  post-image writes it twice, as `uImage-st10` and `uImage-st20`, because the packager checks
  each uImage's name against the model it is for.
- **Rootfs /boot**: `uImage-rhino`, `uImage-binky`, `uImage-ginger` (the same kernel, hard
  links), `uImage-spotty`, `rhino_sm2.dtb` (with 4 KiB headroom), `binky_sm2.dtb`,
  `ginger_sm2.dtb`, `spotty_scm.dtb` and `spotty3_sm2.dtb` (the Series III preview).
  Each speaker's U-Boot boots `/boot/uImage-${variant}` and `/boot/${variant}_${module_type}.dtb`.
- **Post-build**: `rootfs/post-build.sh`, then `image/post-build.sh`. Console, overlay, busybox fragment, device table and UBI geometry are
  the `rootfs` directory's.
- **Bootloaders**: sm2 SPL (`wla-spl`), ST20 SCM SPL (`st20-spl`) and the shared U-Boot
  (`wla-uboot`), from `host-soundtap-bootloaders`. ST20 does not ship a separate U-Boot.
- **Packages**: both codec loaders, bcoflash, linux-firmware's WiLink firmware, the WiLink
  board config regenerated by `soundtap-wl18xx-conf` (ADR 0047), plus
  mtd-utils, which `POST /api/firmware` installs with, and wireless-regdb.

CI (`build.yml`) builds it and uploads the package
as the run's `candidate` artifact. Stock codec scripts are not packaged: each speaker
uses its own retained codec tuning (ADR 0012).
